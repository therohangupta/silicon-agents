# deploy/

Non-secret **configuration snippets** bind-mounted into platform Docker Compose services. This directory is not a deployment chart by itself — the authoritative compose graph lives in **`docker-compose.yml`**, rendered/extended by **`scripts/render_platform_compose.py`** from **`config/platform.yaml`**.

Use **`deploy/`** when a service needs a file on disk inside the container and checking that file into git is clearer than baking defaults into an image or embedding a long heredoc in Compose.

## Current files

| File | Mounted into | Purpose |
|------|--------------|---------|
| [opensearch.yml](opensearch.yml) | `opensearch` service → `/usr/share/opensearch/config/opensearch.yml` (read-only) | Single-node OpenSearch for the **local memory plane** |

### opensearch.yml behavior

Tuned for **local development**, not production:

- **`cluster.name`**: `silicon-memory`
- **`discovery.type`**: `single-node` (no zen/seed host choreography on a laptop)
- **`plugins.security.disabled`**: `true` — plain HTTP inside the Compose network
- **`cluster.routing.allocation.disk.threshold_enabled`**: `false` — avoids common Docker Desktop disk watermark failures

Other Compose services (memory plane, agents with **`MEMORY_BACKEND=plane`**) connect to this node for searchable record copies configured in **`domains.eda.memory.placements`** (**`_SEARCHABLE`** placements include OpenSearch).

## What does not belong here

| Item | Where instead |
|------|----------------|
| Passwords, API keys, TLS private keys | **`.env`** (gitignored), secret manager, or local-only overrides |
| Full Compose manifests | **`docker-compose.yml`**, **`docker-compose.agents.yml`**, generated outputs |
| Agent-specific env | Agent **`config.yaml`** + **`config/platform.yaml`** **`agent_environment`** |
| Database initialization SQL | Platform image or **`packages/`** migration tooling |

## Adding a new snippet

1. Add the file under **`deploy/`** with a short header comment (service name, mount path, intent).
2. Wire a **read-only** volume in **`docker-compose.yml`** (or the template **`render_platform_compose.py`** emits).
3. Document the mount in this README table.
4. If the setting is environment-specific (prod vs dev), prefer env vars in Compose with a dev-default file here rather than forking prod secrets into git.

## Relationship to agent deployment

Agent containers are defined in **`docker-compose.agents.yml`**, generated by **`domains.eda.fleet.render_compose`** / **`scripts/fleet_select.py`**. They generally do **not** mount **`deploy/`** unless an agent needs direct access to the same config (unusual).

Platform services that agents depend on (Postgres, NATS, OpenSearch, gateway, fleet-server, telemetry) consume **`deploy/`** and **`config/platform.yaml`**.

## Troubleshooting OpenSearch in Compose

| Symptom | Likely cause | Mitigation |
|---------|--------------|------------|
| Agent plane search fails with connection refused | OpenSearch container not healthy yet | Wait for healthcheck; retry after **`startup.sh`** platform step |
| Disk allocation errors on startup | Docker Desktop volume nearly full | Free disk or prune images; local config disables watermarks but host disk still matters |
| Security plugin errors | Custom image re-enabled security | Ensure mount still sets **`plugins.security.disabled: true`** for dev |

For production deployments, replace this file with a secured cluster config **outside** git and drop the security-disabled flag — do not copy **`opensearch.yml`** verbatim to prod.

## Checklist: new platform bind-mount

- [ ] File lives under **`deploy/`** with header comment (service, in-container path)
- [ ] Compose volume is **read-only** where possible
- [ ] No secrets in the mounted file
- [ ] Row added to the table at the top of this README
- [ ] **`docs/RUN.md`** updated if bring-up order or smoke tests change

## Memory plane data flow (local)

```text
EdaAgent.publish/query
    → EngineeringMemory (plane backend)
        → Postgres (envelope of record)
        → OpenSearch (searchable copies — config from this directory)
        → Vector / NATS / Cassandra journal (per RecordType placements)
```

OpenSearch settings here only affect **how the node runs**, not **which** records index — placements live in **`domains/eda/memory/placements.py`**. If search returns empty results, verify plane connectivity before editing **`opensearch.yml`**.
